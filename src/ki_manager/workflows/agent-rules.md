# /agent-rules — AI Rules & Guidelines for Project Harnesses (AGENTS.md, CLAUDE.md, IDE Rules)

> [!IMPORTANT]
> **Purpose of this Document**:
> This document is **NOT a system file or magical hook** that automatically or invisibly directs AI agent behavior by its mere presence.
> Rather, it is a **reference guide and collection of actionable snippets and recommendations** for developers and agents to configure project-level instruction files defined in the project harness (`AGENTS.md`, `CLAUDE.md`, `.cursorrules`, `.windsurfrules`).
> Its goal is to ensure external AI agents understand the `ki-manager` architecture and use the available tools properly.

---

## 1. Knowledge Base Directory Layout

Every AI agent working with the repository must distinguish between the **system container** and the **knowledge items directory**:

```
<project_root>/
├── {{KI_DIR}}/                 ← SYSTEM CONTAINER (like .git/ for Git)
│   ├── config.json             ← Environment config (Python venv path, etc.)
│   ├── ki_config.json          ← Knowledge base configuration (knowledge_root: "{{KI_DIR}}")
│   ├── doc_config.json         ← Manifest and registry of tracked modules & KIs
│   ├── DIR_INDEX.md            ← Auto-generated project directory tree
│   ├── coverage_matrix.md      ← Coverage audit report (generated by audit_coverage)
│   ├── knowledge/              ← STRICTLY ALL Knowledge Items (*.ki.md) live HERE!
│   │   ├── _OVERVIEW.ki.md     ← High-level project architecture stub (DO NOT DELETE!)
│   │   └── <module>.ki.md      ← Knowledge Items for individual modules
│   └── decisions/              ← Architecture Decision Records (*.md ADRs)
├── AGENTS.md                   ← Instructions for Antigravity & general AI agents in harness
└── CLAUDE.md                   ← Instructions for Claude Code / Anthropic
```

> [!CAUTION]
> **Common Agent Pitfalls:**
> 1. **`knowledge_root: "{{KI_DIR}}"` points to the root of the system container, NOT the folder for `.ki.md` files.**
>    NEVER write `*.ki.md` files directly into the root of `{{KI_DIR}}/`.
> 2. **NEVER delete `{{KI_DIR}}/knowledge/`!**
>    The initial `_OVERVIEW.ki.md` (~640 bytes) is NOT a stale duplicate. It is the initial bootstrap stub created for enrichment. Deleting `knowledge/` breaks all analysis and scaffolding tools (`audit_coverage`, `analyze_dependencies`, `ki_scaffold`, `finalize_ki_scaffolds`).

## 2. Reference Snippet for `AGENTS.md` (Antigravity & General AI Agents)

Add the following block to your project's `AGENTS.md` (or use `sync_agents_md` to keep tables synchronized):

```markdown
# AI Agent Guidelines (AGENTS.md)

This project uses **ki-manager** (an MCP server for architectural knowledge management).

## Knowledge Base Architecture
- System container: `{{KI_DIR}}/`
- Knowledge Items (KIs): strictly inside `{{KI_DIR}}/knowledge/*.ki.md`
- Architecture Decision Records (ADRs): in `{{KI_DIR}}/decisions/*.md` (or `decisions/`)
- Project overview & entry point: `{{KI_DIR}}/knowledge/_OVERVIEW.ki.md`
- Project directory tree: `{{KI_DIR}}/DIR_INDEX.md`

## Agent Operating Rules
1. **Context Before Changes**:
   - Inspect `{{KI_DIR}}/knowledge/_OVERVIEW.ki.md` first.
   - Read relevant module KIs via `ki_read(rel_path="...")` or `read_know_file` before writing code.
   - List read KIs and architectural constraints in your Implementation Plan.
2. **File Safety**:
   - NEVER delete `{{KI_DIR}}/knowledge/` and never save `.ki.md` files directly in `{{KI_DIR}}/` root.
   - Use `ki-manager` tools (`write_know_file`, `edit_know_file`) rather than generic filesystem tools when modifying documentation.
3. **Synchronization**:
   - When modifying module logic, update the corresponding KI and run `sync_agents_md`.

|------|-----------------|
| `_OVERVIEW.ki.md` | Project overview |

```

## 3. Reference Snippet for `CLAUDE.md` (Claude Code / Anthropic)

Add the following block to your project's `CLAUDE.md`:

```markdown
# Project Guidelines for Claude Code

This project uses `ki-manager` MCP server for knowledge management.

## Knowledge Base Architecture
- System container: `{{KI_DIR}}/`
- Knowledge Items (KIs): strictly inside `{{KI_DIR}}/knowledge/*.ki.md`
- Architecture Decision Records (ADRs): inside `{{KI_DIR}}/decisions/*.md`
- Project overview: `{{KI_DIR}}/knowledge/_OVERVIEW.ki.md`

## Core Protocols
- **Always read context first**: Check `{{KI_DIR}}/knowledge/_OVERVIEW.ki.md` and relevant KIs before implementing changes.
- **Never mutate container root**: Do NOT write `*.ki.md` directly into `{{KI_DIR}}/`. Never delete `{{KI_DIR}}/knowledge/`.
- **Tooling**: Prefer MCP tools (`ki_read`, `ki_search`, `write_know_file`) when inspecting or updating documentation.
- **Verification**: Run tests via project virtual environment (`.venv`).
```

## 4. Reference Snippet for Cursor (`.cursorrules` or `.cursor/rules/ki-manager.mdc`)

```markdown
---
description: Rules for navigating and updating ki-manager knowledge base
globs: ["**/*"]
alwaysApply: true
---

# ki-manager Integration Rules

- Project architecture is documented via Knowledge Items (KIs) located in `{{KI_DIR}}/knowledge/`.
- Start exploring codebase with `{{KI_DIR}}/knowledge/_OVERVIEW.ki.md` and `{{KI_DIR}}/DIR_INDEX.md`.
- When writing or updating documentation, always keep `*.ki.md` files inside `{{KI_DIR}}/knowledge/`.
- Do NOT delete or modify the container directory structure (`{{KI_DIR}}/`).
```

## 5. Tooling Interaction

Depending on the active `--tool-mode` of the `ki-manager` MCP server, use the corresponding tools:

<!-- if-compact -->
- **Search documentation**: `ki_search(query="<keywords>")`
- **Read KI or ADR**: `ki_read(rel_path="<filename>.ki.md")`
- **Inspect tool catalog**: `ki_tools()`
- **Coverage audit**: `ki_call(tool="audit_coverage")`
- **Write / update KI**: `ki_mutate(tool="write_know_file", args={"rel_path": "<name>.ki.md", "content": "..."})`
- **Sync AGENTS.md**: `ki_mutate(tool="sync_agents_md")`
<!-- else-compact -->
- **Search documentation**: `ki_search(query="<keywords>")`
- **Read KI or ADR**: `ki_read(rel_path="<filename>.ki.md")` or `read_know_file(rel_path="<filename>.ki.md")`
- **Coverage audit**: `audit_coverage()`
- **Write / update KI**: `write_know_file(rel_path="<name>.ki.md", content="...")`
- **Sync AGENTS.md**: `sync_agents_md()`
<!-- /if-compact -->
