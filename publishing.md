# Чеклист публикации в PyPI (Release Checklist)

Для успешной публикации новой версии пакета `ki-manager` через GitHub Actions, необходимо выполнить эти шаги **строго в указанном порядке**.

## Почему Action может не запуститься?
1. Файла `.github/workflows/publish.yml` не было в истории коммитов на момент создания тега (например, ты создал тег на старом коммите).
2. Забыл поменять версию в файлах проекта — сборщик сгенерировал пакет со старой версией, и PyPI его отклонил.

---

## 📝 Пошаговый чеклист

### Шаг 0: Предрелизная верификация
Запустите проверку тестов и сборки пакета локально:
```bash
python scripts/verify_release.py
```

### Шаг 1: Обновление версии в коде и документации
Перед созданием тега укажите новую версию в конфигурации пакета:

1. **`pyproject.toml`**: `version = "X.Y.Z"`
2. **`src/ki_manager/__init__.py`**: `__version__ = "X.Y.Z"`

Также актуализируйте **`CHANGELOG.md`** (*ведется строго на английском языке* по стандарту Keep a Changelog):
- Фокусируйтесь на поведении инструментов и ценности для пользователей, избегая внутренних путей к файлам реализации и приватных функций.
- Перенесите изменения из секции `[Unreleased]` в новую секцию `## [X.Y.Z] — YYYY-MM-DD`.
- Добавьте ссылку для сравнения версий внизу файла.

### Шаг 2: Коммит и пуш изменений
Изменения версий и чейнджлога должны попасть в основную ветку (обычно `main`) **ДО** создания тега.

```bash
git add pyproject.toml src/ki_manager/__init__.py CHANGELOG.md
git commit -m "Bump version to X.Y.Z"
git push origin main
```

### Шаг 3: Создание и пуш тега
Пайплайн публикации настроен на срабатывание **только при пуше тега**, начинающегося с буквы `v`.

```bash
# Обязательно добавь префикс 'v'
git tag v2.0.2

# Запушь тег на GitHub (это действие триггерит Action)
git push origin v2.0.2
```

### Шаг 4: Проверка в GitHub Actions
1. Открой вкладку **Actions** в репозитории на GitHub.
2. Убедись, что процесс **Build and publish** появился в списке и выполняется.
3. Дождись зелёной галочки. Пакет появится на **PyPI**.
